# Contributing

## Releasing

Releases are published to npm from GitHub Actions with [trusted publishing](https://docs.npmjs.com/trusted-publishers), so no npm token is stored and every version carries a provenance attestation. To release, bump `version` in `package.json`, in `plugin/.claude-plugin/plugin.json` and in the pinned commands of `README.md` (tests keep them equal), merge it to `main`, then push a matching tag:

```sh
git tag v0.1.0
git push origin v0.1.0
```

The `Release` workflow fails without publishing when the tag does not match the package version, or when `vp check`, `vp test` or `vp pack` fails.

It also publishes an `npm-shrinkwrap.json`, generated by `scripts/write-shrinkwrap.ts` and not committed, that locks the production dependencies to the versions in `pnpm-lock.yaml`, the ones `vp test` ran. This is what makes a pinned `npx rulebookguard@<version>` reproducible for projects with no lockfile entry for it, so to ship a newer dependency, update `pnpm-lock.yaml`. The workflow fails without publishing when a package resolves to two versions in `pnpm-lock.yaml`, when npm cannot lock exactly those versions, or when the packed CLI cannot lint this repository.
